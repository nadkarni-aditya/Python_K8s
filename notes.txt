## APP

pydantic used to validate data and types sent in api calls

a python package is just a folder with __init__.py 

example:

from fastapi import FastAPI
from fastapi.params import Body
from pydantic import BaseModel
from typing import Optional
from random import randrange

Example starter code and Pydantic data validation schema:

class PyDanticMediaPost(BaseModel):
    title: str
    content: str
    published: bool = True #setting a default value if post call doesn't have this
    rating: Optional[int] = None

app = FastAPI()



To separate routes, we can create a folder called routers and then put all the different routes in their, then we just add to main.py app.include_router(auth.router)


Summary of stack so far: -----------------------------------------------------------------

FastAPI - creates the api routes/endpoints, handles requests/responses and turns our python functions into a working web api

psycopg2 - low level driver, lets python talk to postgres, sends raw SQL and gets back raw rows

SQLAlchemy - ORM, lets us use python classes/objects instead of raw SQL, models.py defines tables as classes

pydantic - validates request/response payload data and types, also auto generates api docs from the schemas

passlib CryptContext (bcrypt) - hashes passwords before storing, and verifies plain password against hash on login

python-jose (jose) - creates and decodes JWT access tokens, used in oauth2.py to sign token with secret key + expiry

alembic - manages database migrations for SQLAlchemy models, keeps schema changes versioned instead of using create_all in code. use alembic revision --autogenerate and alembic upgrade head

## INFRA

# DEV LOOP (order matters)
1. docker build -t fastapi-app:latest .
2. kind load docker-image fastapi-app:latest --name practicelab
3. kubectl apply -f <manifest>.yaml
4. kubectl rollout restart deployment fastapi-app
5. kubectl port-forward svc/fastapi-app 5000:8000   (dev-only doorway in)

# #1 FORK — what did I change?
- CODE (main.py/requirements) → full rebuild loop (build → kind load → rollout)
- CONFIG (any .yaml) → just kubectl apply -f
- SCHEMA (new migration) → kubectl exec deploy/fastapi-app -- alembic upgrade head

# OBJECTS (all share: apiVersion/kind/metadata/spec)
- Deployment = keep N pods of an image alive (self-healing). Owns replicas, image, probes, envFrom.
- Service = stable address in front of pods; finds them by LABEL not IP. Owns selector, port, targetPort.
- ConfigMap/Secret = config injected via envFrom; OVERRIDES any baked-in .env.

# PORTS
containerPort/app = 8000. Service port=8000, targetPort=8000.
port-forward LEFT=any free Mac port, RIGHT=Service's real port (8000).

# RULES LEARNED THE HARD WAY
- ONE object = ONE file. apply reconciles to the WHOLE file — omitting envFrom DELETES it (localhost error returns).
- replicas: 1 = kill pod = total outage. replicas: 2 = seamless self-heal. Zero-downtime needs replicas>=2 + readiness probe.
- port-forward is bound to ONE pod; rollout/chaos kills it. Restart it, or: while true; do kubectl port-forward svc/fastapi-app 5000:8000; sleep 1; done

# COMMON ISSUES → FIX
- 500 "localhost:5432 refused" → DATABASE_HOSTNAME must = postgres (service name), via envFrom.
- 500 'relation "users" does not exist' → kubectl exec -it deploy/fastapi-app -- alembic upgrade head
- 404 on endpoint → route not in running image (edited but never rebuilt). 404 = app layer.
- ImagePullBackOff/ErrImageNeverPull → image not loaded in kind, or tag mismatch. Rebuild + kind load exact tag.
- Every request 500 after new library → version incompat (instrumentator 7.0.0 vs new FastAPI). Traceback path names the culprit.

# DEBUG
kubectl get pods -l app=fastapi-app          # STATUS/READY
kubectl logs -l app=fastapi-app --tail=30    # traceback at bottom
kubectl exec deploy/fastapi-app -- printenv  # what env the app ACTUALLY has
kubectl get endpoints fastapi-app            # pod IPs (empty = selector mismatch)

# DIAGNOSIS FORK — which layer?
curl works, client fails → client/Locust. curl fails → app or tunnel.
4xx/5xx from app → app layer. connection refused/hang → network/tunnel.
client logs errors but server logs 0 → failure BETWEEN them (port-forward), not the app. Server logs = ground truth. 



## O11Y

1. App exposes metrics. Add to main.py:

python
from prometheus_fastapi_instrumentator import Instrumentator
Instrumentator().instrument(app).expose(app, endpoint="/metrics")

Add prometheus-fastapi-instrumentator==8.1.0 to requirements.txt. Then rebuild loop (build → kind load → rollout restart). This gives you /metrics.

2. Install the monitoring stack via Helm (one bundle = Prometheus + Grafana + wiring):

bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install monitoring prometheus-community/kube-prometheus-stack -n monitoring --create-namespace

3. Name your Service's port (ServiceMonitor references ports by name) — add to service.yaml:

yaml
  ports:
  - name: http
    port: 8000
    targetPort: 8000

kubectl apply -f service.yaml

4. Tell Prometheus to scrape your app — a ServiceMonitor:

yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: fastapi-app
  namespace: monitoring
  labels:
    release: monitoring        # REQUIRED — this stack's Prometheus only adopts monitors with this label
spec:
  selector:
    matchLabels:
      app: fastapi-app
  namespaceSelector:
    matchNames: [default]
  endpoints:
  - port: http                 # matches the NAMED service port
    path: /metrics
    interval: 5s

kubectl apply -f servicemonitor.yaml

5. Verify the scrape (before touching Grafana):

bash
kubectl -n monitoring port-forward svc/monitoring-kube-prometheus-prometheus 9090:9090
# open localhost:9090/targets → look for fastapi-app = UP

6. Open Grafana:

bash
kubectl -n monitoring port-forward svc/monitoring-grafana 3000:80
# password:
kubectl -n monitoring get secret monitoring-grafana -o jsonpath="{.data.admin-password}" | base64 -d ; echo
# localhost:3000, admin / <password>

7. Build 3 panels (New dashboard → Add visualization → Prometheus datasource → Code mode):

RPS: sum(rate(http_requests_total{handler!="/metrics"}[1m])) by (handler)
p95: histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket{handler!="/metrics",handler!="/login"}[5m])) by (le, handler))
Errors: sum(rate(http_requests_total{status=~"5.."}[1m])) by (handler)
