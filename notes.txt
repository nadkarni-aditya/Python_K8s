pydantic used to validate data and types sent in api calls

a python package is just a folder with __init__.py 

example:

from fastapi import FastAPI
from fastapi.params import Body
from pydantic import BaseModel
from typing import Optional
from random import randrange

Example starter code and Pydantic data validation schema:

class PyDanticMediaPost(BaseModel):
    title: str
    content: str
    published: bool = True #setting a default value if post call doesn't have this
    rating: Optional[int] = None

app = FastAPI()



To separate routes, we can create a folder called routers and then put all the different routes in their, then we just add to main.py app.include_router(auth.router)


Summary of stack so far: -----------------------------------------------------------------

FastAPI - creates the api routes/endpoints, handles requests/responses and turns our python functions into a working web api

psycopg2 - low level driver, lets python talk to postgres, sends raw SQL and gets back raw rows

SQLAlchemy - ORM, lets us use python classes/objects instead of raw SQL, models.py defines tables as classes

pydantic - validates request/response payload data and types, also auto generates api docs from the schemas

passlib CryptContext (bcrypt) - hashes passwords before storing, and verifies plain password against hash on login

python-jose (jose) - creates and decodes JWT access tokens, used in oauth2.py to sign token with secret key + expiry

alembic - manages database migrations for SQLAlchemy models, keeps schema changes versioned instead of using create_all in code. use alembic revision --autogenerate and alembic upgrade head
